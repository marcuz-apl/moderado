# M7.3 guarded public release workflow Design

**Milestone:** M7.3

## Goal

Make npm and GitHub Release publication an explicit, reviewable maintainer action.

## Architecture

A workflow_dispatch workflow requires a confirmation input and release tag, runs offline verification, uses npm provenance, and creates the GitHub Release only after its checks pass.

## Scope

Workflow permissions, manual inputs, package verification, npm trusted publishing, artifact release, and workflow tests. Automatic release-on-push and stored npm tokens are excluded.

## Testing

Inspect workflow text and run package verification offline. Live publishing is intentionally outside automated tests.

## Release notes

This document records the intended boundary and verification criteria for M7.3. It does not authorize external publication or relax Moderado's approval-first policy.
