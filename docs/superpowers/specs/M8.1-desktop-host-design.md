# M8.1 Desktop Host and IPC Design

**Status:** Proposed design

Moderado’s desktop client will use Tauri with a separate Node.js agent process.
The existing core, providers, tools, approvals, sessions, and web search remain
in the agent process; the desktop window is a presentation host.

## Boundary

The renderer communicates only through a narrow typed IPC protocol. It cannot
read workspace files, execute commands, access provider keys, or disable an
approval requirement. The agent validates every message and binds approval
responses to the pending request ID and exact action.

## Message families

- `session_start`, `session_resume`, `session_stop`
- `user_prompt`, `cancel_request`
- `agent_event` for progress, model changes, tool results, citations, and completion
- `approval_request`, `approval_response`
- `diagnostic_request`, `diagnostic_response`

Messages carry a protocol version, request ID, timestamp, and validated payload.
Unknown message types, stale approval IDs, and malformed payloads fail closed.

## Security

The desktop host never receives raw API keys. Credential storage stays in the
agent process using the existing OS-backed credential layer. Workspace paths
and tool arguments are revalidated at the agent boundary. Disconnects cancel
pending work and deny unresolved approvals.

## Technology decision

Use Tauri for the desktop shell and keep the Node agent as a child process. This
preserves the existing TypeScript codebase, keeps the renderer lightweight, and
leaves room for a future native component without rewriting the agent core.
