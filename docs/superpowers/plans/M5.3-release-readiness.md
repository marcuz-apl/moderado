# Release Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the CLI package inspectable for npm distribution and record local, redacted operational failures.

**Architecture:** Keep package release metadata in `apps/cli/package.json`. Add a small CLI-only JSON Lines logger that accepts a command and error, redacts common secret formats, and ignores filesystem failures. The entry point records unhandled command failures without coupling core, tools, or providers to logging.

**Tech Stack:** TypeScript, Node.js standard library, Vitest, npm.

**Spec:** `docs/superpowers/specs/M5.3-release-readiness-design.md`

## Global Constraints

- Support Node.js 20 or newer and introduce no runtime dependencies.
- Keep automated tests offline; live connectivity remains opt-in.
- Logs must never contain credential values, request bodies, tool output, or workspace content.
- Do not publish a package or create release automation in this milestone.
