# M6.3 package manager manifests Implementation Plan

> **For agentic workers:** Execute test-first, keep the change within existing workspace boundaries, and run the full offline suite before committing.

**Goal:** Generate reviewable package-manager manifests from verified binary release artifacts without publishing to any external channel.

**Architecture:** A Node script reads the checked artifact manifest and checksums, then renders Homebrew, Scoop, winget, and AUR files. Generation is deterministic and remains separate from third-party repository submission.

**Tech Stack:** TypeScript, Node.js standard library, Zod where external data is parsed, Vitest.

**Spec:** docs/superpowers/specs/M6.3-package-manager-manifests-design.md

## Global Constraints

- No new runtime dependency without owner approval.
- Keep provider, tool, and CLI boundaries intact.
- Automated tests remain offline and deterministic.
- Do not publish, upload, or contact a live provider during verification.

## Tasks

1. Add failing temporary-manifest tests. 2. Generate each channel manifest from the release manifest. 3. Run focused tests and the full offline suite. 4. Document that generated manifests require owner-reviewed external submission.
