# M7.3 guarded public release workflow Implementation Plan

> **For agentic workers:** Execute test-first, keep the change within existing workspace boundaries, and run the full offline suite before committing.

**Goal:** Make npm and GitHub Release publication an explicit, reviewable maintainer action.

**Architecture:** A workflow_dispatch workflow requires a confirmation input and release tag, runs offline verification, uses npm provenance, and creates the GitHub Release only after its checks pass.

**Tech Stack:** TypeScript, Node.js standard library, Zod where external data is parsed, Vitest.

**Spec:** docs/superpowers/specs/M7.3-guarded-public-release-workflow-design.md

## Global Constraints

- No new runtime dependency without owner approval.
- Keep provider, tool, and CLI boundaries intact.
- Automated tests remain offline and deterministic.
- Do not publish, upload, or contact a live provider during verification.

## Tasks

1. Add workflow contract tests. 2. Implement guarded workflow inputs and permissions. 3. Add release documentation. 4. Verify package artifacts locally.
