# M6.4 release execution Implementation Plan

> **For agentic workers:** Execute test-first, keep the change within existing workspace boundaries, and run the full offline suite before committing.

**Goal:** Define the maintainer-controlled publication process for an explicitly chosen public release.

**Architecture:** The existing guarded GitHub workflow is the only publication entry point. It publishes verified npm and GitHub Release artifacts after explicit owner selection; generated package-manager manifests are submitted separately.

**Tech Stack:** TypeScript, Node.js standard library, Zod where external data is parsed, Vitest.

**Spec:** docs/superpowers/specs/M6.4-release-execution-design.md

## Global Constraints

- No new runtime dependency without owner approval.
- Keep provider, tool, and CLI boundaries intact.
- Automated tests remain offline and deterministic.
- Do not publish, upload, or contact a live provider during verification.

## Tasks

1. Verify package and binary artifacts locally. 2. Review workflow release gates. 3. Dispatch only after owner approval. 4. Validate downloaded release assets and submit reviewed manifests.

## Verification

Run 
pm.cmd test, 
pm.cmd run build, and git diff --check. Record any live-release action separately because it requires explicit owner approval.
