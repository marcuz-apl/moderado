# M6.1 Standalone npm Installation and Release Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Produce a self-contained `moderado` npm tarball that works after a global install, and verify it in a manually triggered release workflow without publishing it.

**Architecture:** Keep development as TypeScript workspaces. A repository-owned Node script copies compiled internal workspace outputs into `apps/cli/dist/vendor/` and rewrites only known `@moderado/*` ESM import specifiers to paths relative to each compiled file. A second Node script packs, inspects, installs, and smoke-tests the tarball; GitHub Actions invokes that release check and uploads the resulting package artifact.

**Tech Stack:** TypeScript, Node.js 20 standard library, npm, Vitest, GitHub Actions.

**Spec:** `docs/superpowers/specs/M6.1-standalone-npm-release-gate-design.md`

## Global Constraints

- Introduce no runtime or build dependencies.
- Retain workspace package boundaries and TypeScript source import specifiers.
- Vendor only compiled internal runtime output; never source files, tests, user configuration, logs, sessions, or credentials.
- Keep `npm test` entirely offline and provider-free.
- The release workflow must not invoke `npm publish` or accept an npm token.
- Support Node.js 20 or newer.

- [x] **Step 3: Implement package verification**

```js
export function verifyPackedFiles(files) {
  for (const file of files) {
    if (file.includes('/node_modules/')) throw new Error(`node_modules is forbidden: ${file}`);
    if (/^package\/(src|tests)\//.test(file)) throw new Error(`source file is forbidden: ${file}`);
    if (/^package\/(\.moderado|logs|sessions|config)/.test(file)) throw new Error(`user data is forbidden: ${file}`);
  }
}
```

The executable path runs `npm pack --json --ignore-scripts` in `apps/cli`, parses its JSON result, validates its file list, installs the tarball under a fresh temporary `--prefix`, invokes the installed `moderado --help`, and removes the temporary directory in `finally`.

**Files:**

**Interfaces:**
- The workflow runs on `workflow_dispatch` and pushed `v*` tags.

- The workflow contains no `npm publish`, `NODE_AUTH_TOKEN`, or npm registry secret.

- [x] **Step 3: Add the release workflow**

```yaml
name: Verify release package
on:
  workflow_dispatch:
  push:
    tags: ['v*']
permissions:
  contents: read
jobs:
  verify-package:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - name: Verify tag matches the release version
        if: github.ref_type == 'tag'
        run: test "$GITHUB_REF_NAME" = "$(cut -d+ -f1 VERSION)"
      - run: npm test
      - run: npm run verify:package
      - uses: actions/upload-artifact@v4
        with: { name: moderado-npm-package, path: apps/cli/*.tgz }
```

Keep GitHub permissions read-only and do not add a publish job.

- [x] **Step 4: Run the focused workflow test**

Run: `npm test -- apps/cli/tests/release_workflow.test.ts`  
Expected: PASS.
