# M7.6 real time web answers Implementation Plan

> **For agentic workers:** Execute test-first, keep the change within existing workspace boundaries, and run the full offline suite before committing.

**Goal:** Answer current-information questions in seconds by searching hosted provider sites before inference instead of letting a model deliberate and then apologize for missing live data.

**Architecture:** `packages/tools` owns a bounded search tool that cascades through a configured endpoint, Exa, and Parallel, validating every payload and returning citation metadata. `apps/cli` detects current-information questions, runs the configured tool, and hands the evidence to a single model turn.

**Tech Stack:** TypeScript, Node.js standard library (`fetch`, `AbortSignal`), Zod for external payloads, Vitest.

**Spec:** docs/superpowers/specs/M7.6-real-time-web-answers-design.md

## Global Constraints

- No new runtime dependency without owner approval.
- Keep provider, tool, and CLI boundaries intact; the model supplies only `query`, an optional `objective`, optional `maxResults`, or an advanced `endpoint` override.
- Automated tests remain offline and deterministic through injected fetch implementations.
- Do not publish, upload, or contact a live provider during verification.

## Tasks

1. Add failing offline tests for search-site ordering, fallback, timeout, payload parsing, citation extraction, and context bounding.
2. Implement the search-site cascade with bounded timeouts and citation metadata, and keep `web_search` automatic.
3. Wire the CLI lane: detect current-information questions, search first, then answer in one model turn.
4. Steer the core system prompt away from `run_command` network lookups and capability apologies.
5. Run the focused and full offline suites, then update TOOLS, ROUTING, SECURITY, roadmap, and handoff documentation.

## Verification

Run `npm.cmd test`, `npm.cmd run build`, and `git diff --check`. Record a live provider probe separately because it contacts an external service.

## Follow-up: answer shaping

Completed after the first M7.6 answers shipped, because live answers read like a retrieval dump — several pages plus a source list — instead of a direct answer.

- The fast-lane task now fixes the reply shape: one context line naming the subject with its place or date, then 3–6 short bullets of concrete values with units, plus an explicit ban on URLs, page titles, site names, and search narration.
- `web_search`'s description and the core system prompt carry the same rule, so a model-initiated search answers in the same shape.
- Without a connected provider the CLI prints a readable excerpt: block metadata lines (`Title:`, `URL:`, `Published:`, `Author:`, `Highlights:`), `---` separators, bare URLs, and markdown markers are dropped, and the digest is capped at ten lines.
- Source URLs stay in tool metadata and remain available when the user explicitly asks for them.
